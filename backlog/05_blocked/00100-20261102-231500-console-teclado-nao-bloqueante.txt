OBJETIVO E CONTEXTO
Atualmente, as operações de leitura de teclado no barramento de E/S da máquina virtual
(IJKL_VM_IO_PORT_CONSOLE_CHAR em src/vm/vm_io.c) utilizam a função getchar(), que é
estritamente bloqueante e requer que o terminal confirme a linha (Enter). Isso impede
que aplicações iterativas em ijkLang realizem processamento intensivo em segundo plano
enquanto consultam periodicamente se o usuário pressionou alguma tecla (como ESC para
cancelamento). Esta tarefa estabelece a infraestrutura necessária de sondagem não-bloqueante
de teclado na VM e a respectiva exposição na biblioteca padrão ijkL.IO.Console.

RESULTADO ESPERADO E OBSERVADO
Esperado: A biblioteca ijkL.IO.Console oferece as rotinas hasKey(): bool e readKeyAsync(): char.
A rotina hasKey() retorna true imediatamente se uma tecla estiver disponível no buffer de
entrada, sem travar o processamento da CPU. Caso contrário, retorna false.
Observado: Apenas readLine() e readKey() bloqueantes existem; qualquer tentativa de consultar
o teclado interrompe a execução até que haja entrada do usuário.
Impacto: Bloqueia as aplicações que necessitam de cancelamento cooperativo via tecla ESC
(como a busca do 1000º primo e a busca em dicionários com cancelamento).

AMBIENTE E REPRODUÇÃO
- Windows 11 x64, Visual Studio / MSBuild C11 (_kbhit de <conio.h>).
- Linux / Ubuntu x86_64, GCC C11 (select / poll com termios em modo raw/cbreak sem eco).
- Código ijkLang de teste:
    while (!ijkL.IO.Console.hasKey()) {
        // executa computação contínua
    }

ESCOPO E LIMITES
Dentro do escopo:
- Distinção clara entre backend de barramento, modo padrão CI e modo nativo:
  1. Barramento da VM (include/vm/vm_io.h e src/vm/vm_io.c):
     - Porta IJKL_VM_IO_PORT_CONSOLE_KEY_AVAILABLE (0x0005).
     - Backend C multiplataforma: Windows (_kbhit de <conio.h>), Linux (select/poll não-bloqueante sobre STDIN_FILENO em <sys/select.h>/<unistd.h>).
  2. Implementação em CI (Modo Padrão):
     - lib/ijkL/IO/Console.ijk com rotinas hasKey(): bool e readKeyAsync(): char emitindo instruções assembly CI (bloco asm com 'in 0x0005, r0').
     - Mapear aliases equivalentes em português no namespace ijkL.ES.Console via keywords/pt-BR.words (temTecla(): bool, leiaTeclaAssincrona(): char).
  3. Despacho Nativo de Builtins (Modo --native-builtins):
     - Compilador (src/compiler/codegen.c): reconhecer rotinas como alvos de builtins nativos (__builtin_console_has_key, __builtin_console_read_key_async), emitindo 'call #__builtin_console_*'.
     - VM (src/vm/vm_core.c): registrar e despachar builtins em execute_native_builtin() executando rotinas nativas em C.
- Paridade Semântica e Testes Determinísticos:
  - Assinaturas, convenções de chamada, retornos e comportamento rigorosamente idênticos entre os modos.
  - Como o teclado é fonte externa não-determinística, os testes de paridade automatizados devem usar ambientes controlados:
    a) Cenário sem entrada (buffer vazio / stream fechada): hasKey() retorna false imediatamente e readKeyAsync() retorna 0 em ambos os modos, sem bloquear CPU.
    b) Cenário com entrada injetada (stream pré-carregada): hasKey() retorna true e readKeyAsync() consome e retorna o mesmo caractere em ambos os modos.
- Adicionar testes de unidade e integração cobrindo os modos padrão e --native-builtins em tests/run_tests.ps1 e Makefile.
Fora do escopo:
- Criação de interface gráfica ou emuladores complexos de terminal ANSI.

Alterações e decisões:
- Console.ijk implementa hasKey e readKeyAsync com in 0x0005/0x0006.
  A porta 0x0006 é adicional: faz a leitura sem recorrer à porta bloqueante.
- codegen.c reconhece os nomes mangled sem parâmetros ($void) e emite chamadas
  __builtin_console_has_key / __builtin_console_read_key_async no modo nativo.
- vm_core.c despacha ambos os builtins em C pelo backend compartilhado,
  preservando convenções de chamada e representação dinâmica inteira de in.
- vm_io.c usa poll/termios no POSIX, _kbhit/_getch no console Windows e
  PeekNamedPipe para pipes Windows. EOF não é tecla. Guarda um byte por VM
  para consultas repetidas não consumirem a entrada. Stdin usa _IONBF para
  não esconder bytes em buffers stdio. Leituras bloqueantes recuperam o byte
  antecipado por ungetc; teste misto com readLine cobre esta interoperabilidade.
- Atributos POSIX são restaurados a cada consulta; sinais de término/suspensão
  são adiados durante essa alteração. Não há handlers persistentes de sinal.
- Aliases portugueses foram adicionados em keywords/pt-BR.words usando o
  mecanismo existente de namespaces/membros. Não há arquivo duplicado em
  lib/ijkL/ES/Console.ijk: esse namespace já resolve para ijkL.IO.Console.
  Escopo/aceite acima refletem essa decisão sem mudar as APIs solicitadas.
- Para cumprir zero warnings no GCC, corrigidos dois avisos preexistentes:
  delimitador de comentário em lexer.c e comparação signed/unsigned em vm_io.c.
- Adicionados testes/fixtures de console, runner Python 3 no Ubuntu (biblioteca
  padrão) e runner PowerShell no Windows; integrados nas suítes gerais e no
  alvo make test-console. Documento de E/S atualizado com contrato e comandos.
