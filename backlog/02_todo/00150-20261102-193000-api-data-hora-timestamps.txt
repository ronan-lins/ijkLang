OBJETIVO E CONTEXTO
O ecossistema ijkLang atualmente carece de módulos para manipulação e obtenção do relógio
do sistema operacional, data, hora civil e timestamps. Essa funcionalidade é indispensável
para registro de eventos, medição de tempo de execução, ordenação temporal e para semear
geradores de números aleatórios com base no horário do dia. Esta tarefa estabelece uma API
minimalista, pragmática e elegante inspirada nos modelos consolidados de Java (Instant,
LocalDateTime) e .NET (DateTime), aderente aos padrões de código da biblioteca ijkLang.

RESULTADO ESPERADO E OBSERVADO
Esperado: Disponibilização da unidade canônica ijkL.Time.DateTime (e alias ijkL.Tempo.DataHora)
fornecendo criação de instâncias de data/hora, consulta de componentes (ano, mês, dia, hora,
minuto, segundo), cálculo dos segundos decorridos do dia (elapsedSecondsOfDay) e conversão para
string formatada ISO 8601 (YYYY-MM-DD HH:MM:SS).
Observado: Inexistência de módulos de tempo em lib/ijkL/ ou suporte a relógio do sistema no
barramento da máquina virtual.
Impacto: Bloqueia a criação do gerador de números aleatórios semeado pelo relógio e a medição
de tempo de tarefas.

AMBIENTE E REPRODUÇÃO
- Windows 11 x64, Visual Studio / MSBuild C11 (<time.h>, GetSystemTimeAsFileTime ou timespec_get).
- Linux / Ubuntu x86_64, GCC C11 (<time.h>, clock_gettime com CLOCK_REALTIME).
- Exemplo de uso pretendido em ijkLang:
    import ijkL.Time.DateTime;
    var agora = ijkL.Time.DateTime.now();
    var segundos_do_dia = ijkL.Time.DateTime.elapsedSecondsOfDay(agora);
    escrevaLinha(ijkL.Time.DateTime.toString(agora));

ESCOPO E LIMITES
Dentro do escopo:
- Distinção clara entre barramento de hardware, modo padrão CI e modo nativo:
  1. Barramento da VM (include/vm/vm_io.h e src/vm/vm_io.c):
     - IJKL_VM_IO_PORT_SYSTEM_TIME_SECONDS (0x0008): timestamp Unix Epoch em segundos (time_t).
     - IJKL_VM_IO_PORT_SYSTEM_TIME_MILLIS (0x0009): fração de milissegundos atuais (0 a 999).
     - Backend em C multiplataforma via time() / timespec_get() / clock_gettime().
  2. Implementação em CI (Modo Padrão):
     - lib/ijkL/Time/DateTime.ijk (e alias em lib/ijkL/Tempo/DataHora.ijk):
       - struct DateTime { int year; int month; int day; int hour; int minute; int second; int millisecond; int timestamp; }
       - public now(): DateTime (lê portas 0x0008 e 0x0009 e decompõe em CI)
       - public utcNow(): DateTime
       - public fromUnixTimestamp(int timestamp_seconds): DateTime (cálculo de calendário gregoriano em CI)
       - public elapsedSecondsOfDay(DateTime dt): int
       - public toString(DateTime dt): string (formatação 'YYYY-MM-DD HH:MM:SS')
  3. Despacho Nativo de Builtins (Modo --native-builtins):
     - Compilador (src/compiler/codegen.c): reconhecer rotinas como alvos de builtins nativos (__builtin_datetime_now, __builtin_datetime_utc_now, __builtin_datetime_from_unix_timestamp, __builtin_datetime_elapsed_seconds_of_day, __builtin_datetime_to_string), emitindo 'call #__builtin_datetime_*'.
     - VM (src/vm/vm_core.c): registrar e despachar builtins em execute_native_builtin() executando rotinas nativas em C que instanciam a mesma struct DateTime e strings na memória da VM.
- Paridade Semântica e Testes Determinísticos:
  - Como o tempo avança continuamente, os testes estritos de paridade não devem comparar chamadas a now() em instantes distintos.
  - Estratégia determinística obrigatória:
    a) Teste de Paridade com Timestamp Fixo: invocar fromUnixTimestamp(1700000000) nos modos padrão (.ci) e nativo (--native-builtins). Todos os campos da struct (year, month, day, hour, minute, second), o resultado de elapsedSecondsOfDay e a string de toString devem ser 100% idênticos entre os modos.
    b) Teste de Sanidade de now() / utcNow(): validar coerência temporal em ambos os modos com tolerância para variação de relógio do SO.
- Adicionar cobertura de testes para ambos os modos em tests/run_tests.ps1 e Makefile.
Fora do escopo:
- Cálculos complexos de fusos horários astronômicos ou calendários não-gregorianos.
